# Sanity audit: Tariffia Wallet (2026-10-28)

Scope: repository at `main` (`5f97333` plus local commit `edb9ed8`), the published `baseDebug` APK `tariffia-wallet-debug.apk` (143,899,066 bytes, package `app.tariffia.wallet.dev`, versionName `1.0.0-rc1`, versionCode 185, minSdk 28, targetSdk 37), and the GitHub Actions workflow.

Not verified: runtime behaviour. No device logcat was available, no emulator is available in this environment, and the local Android build does not run. Every claim below is either read from code/APK or marked as unverified.

## 1. Status of the reported problems

| Problem | Status |
| --- | --- |

| Launcher label shows "Tariffia Dev" | **Fixed in source** (`edb9ed8`): debug, ciDebug, ciRelease, fdroidDebug and fdroidCidebug now use "Tariffia Wallet". Installed APK still shows old label until a new build is published. |
| Push to `main` | **Blocked.** The GitHub token in the environment is invalid (`gh auth status`, `git push` returns 401). Commit `edb9ed8` exists only locally. |

## 2. Changes made in this session

- `app/src/{debug,ciDebug,ciRelease,fdroidDebug,fdroidCidebug}/res/values/strings.xml`: `App_Name` set to "Tariffia Wallet".
- `dapp-core/.../DAppManager.kt`: new `disable()` that installs `DAppServiceEmpty`.
- `walletkit/.../core/App.kt` (startup): WalletConnect/Reown is initialised only when `WALLET_CONNECT_PROJECT_ID` is not blank; otherwise dApp support is disabled. Reason: CI builds have no secrets, so the project ID is always empty. Trade-off: WalletConnect is off in every APK built without the secret.
- `.github/scripts/check_release_branding.py` passes.

## 3. Findings by severity

### Critical (must fix before any user-facing release)

1. **No crash evidence yet.** The only confirmed startup fact is that `App.onCreate` (walletkit `App.kt`) runs synchronously and launches several coroutines on `Dispatchers.Default`/`IO` without a `CoroutineExceptionHandler` (`App.kt:586,632,653,685,706`; `WalletManager.kt:44,116,123,136`). An uncaught exception in any of them terminates the process. This is the most likely class of crash, but which one is unknown.
2. **Empty secrets in CI APK.** `WALLET_CONNECT_PROJECT_ID`, `MARKET_API_KEY`, `ALCHEMY_API_KEY`, `TRONGRID_API_KEYS`, `SOLANA_JUPITER_API_KEY`, `TONAPI_KEY`, `UDN_API_KEY`, etc. are read from the environment (`app/build.gradle.kts:56-197`) and are empty in the GitHub Actions build (no secrets are configured). Every feature that depends on them fails at runtime.
3. **Backend hosts do not resolve.** `dev.tariffia.app` and `tariffia.app` are used for market data, coin lists, FAQ and guides (`app/build.gradle.kts:139-196`). Previous notes record that the hosts are not reachable. Market/coin data is therefore unavailable in the APK.
4. **Release signing absent.** Only the `test` keystore (`storePassword = "testKeystore123"` in `app/build.gradle.kts`, `signingConfigs.create("test")`) is used. The keystore password is committed to the repository. Acceptable for a debug APK, not for any release.

### Should fix

5. `AppDatabase.kt:164-166`: database name `dbBankWallet` (upstream name) and `allowMainThreadQueries()`. The second can cause ANR on slow storage; it hides threading bugs instead of fixing them.
6. `AppDatabase.kt:93`: schema version 87, `exportSchema = false`. Migrations cannot be checked against exported schemas in CI.
7. `AppIcon` enum (`AppearanceModule.kt`) and manifest aliases match (Main, Dark, Mono, Ball8, Monero, ZCash, Pepe, Doge, Punk, Ape, Yeschad, Gigachad, Leo, Mustang, Yak). The removed Plflag and Sinwar aliases are not referenced anywhere. This is consistent, but it was not exercised on device.
8. 25 `TODO/FIXME/HACK` markers in Kotlin sources (`rg`). Not individually triaged in this audit.
9. `app/proguard-rules.pro` (368 lines) is applied only to `release` (`isMinifyEnabled = true`). The debug APK is not obfuscated, which is expected.
10. 71 test source files exist (`src/test`, `src/androidTest`). No test is run in the CI workflow; the workflow only builds `assembleBaseDebug`.
11. Workflow `build_test_apk.yml` publishes the release with `overwrite_files: true`; the same asset name is always replaced. A broken build replaces the last good APK.

### Verified OK

- Native libraries (`arm64-v8a`): all 23 ELF shared objects have 16 KB segment alignment. The 4 KB alignment warnings are only for `armeabi-v7a` 32-bit libraries, which do not use 16 KB pages. The Moto G54 page size was not checked; the arm64 libraries satisfy 16 KB alignment either way.
- Manifest: launcher alias targets (`io.horizontalsystems.bankwallet.modules.main.MainActivity`) resolve correctly in the built APK.
- Branding guard passes (no retired branding, no CDN references, no extra metadata locales).
- Translation rule in `AGENTS.md` (all nine locales per string change) was not checked in this session.

## 4. Independence from the original (Unstoppable Wallet 0.54.0)

- **Still derived code:** Kotlin namespace and packages are `io.horizontalsystems.*` throughout (thousands of references). This is an acknowledged derivation (`NOTICE`, README). Renaming the namespace is a large refactor with no runtime benefit.
- **Remaining upstream identifiers:** database file `dbBankWallet`, `docker/build-apk.sh` and `docker/test.sh` still clone and build `horizontalsystems/unstoppable-wallet-android`, `libs.versions.toml` has upstream Kit versions (`moneroKit`, `zcashSdk`, `ethereumKit`, `marketKit` etc.) and `unstoppableDomains` library.
- **Dependencies on upstream libraries:** the Kits (`bitcoinKit`, `ethereumKit`, `marketKit`, `zcashSdk` from Zodl snapshots) are third-party/upstream packages. The app cannot be independent of them without forking those libraries.
- **Removed:** upstream branding assets, metadata locales (13 removed), AllBridge live tracking (`71f1ab2`), HS CDN references (replaced by `TariffiaCdn`, `cedc570`).
- **Conclusion:** Tariffia is an independent product identity (name, icons, CDN paths, metadata, release process), but the code and several dependencies are still Unstoppable Wallet derivatives.

## 5. What is missing

- A real release keystore and the matching SHA-256 fingerprints in `assetlinks/*.json` (both files still have empty arrays).
- Working Tariffia-owned backends: `tariffia.app` and `dev.tariffia.app` do not resolve.
- Provider API keys (Alchemy, Etherscan, BscScan, Blockscout, TronGrid, Jupiter, TONAPI, THORChain, FastNEAR, UDN) and a Reown/WalletConnect project ID. Without them, related features are unavailable.
- Screenshots for store listing (`metadata/en-US`).
- A device or emulator test in CI (no runtime test exists).
- Crash reporting in the app (none is configured; `Timber.DebugTree` only in debug).

## 6. Plan

1. Get the crash text from the Motorola G54 (logcat, or the exact message on screen). Without it, the root cause stays unknown.
2. Push commit `edb9ed8` with a valid GitHub token (`git push origin main`). The workflow then publishes a new APK with the "Tariffia Wallet" label.
3. Add a CI job that installs the APK on an x86_64 emulator (API 35/36) and fails on `FATAL EXCEPTION` in logcat. This catches the startup crash class automatically.
4. Put the `allowMainThreadQueries` and unhandled-coroutine findings into fixes once the crash log confirms which path fails.
5. Provision backends and keys listed in section 5 before any store release.
